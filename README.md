# RailQR Companion Portal — UDM & TMS | Indian Railways

This repository contains the **Unified Companion Portal** for the RailQR supply chain ecosystem. It acts as the official government-side application that receives and processes data from the **GaugeMarket** vendor platform.

This portal seamlessly bridges vendor-side operations with internal railway systems, tracking everything from manufacturing origin to final deployment, risk assessment, and secure administrative operations.

> **Live Deployment:** [https://udmtmsdemo.vercel.app](https://udmtmsdemo.vercel.app)

---

## 🏛️ System Architecture

The portal provides access to two core Indian Railways systems, secured behind a premium Admin Registration Portal:

### 1. UDM (Unified Data Management)
The canonical digital registry for every railway component.
- **Component Lifecycle:** Tracks states from `REGISTERED` → `IN_TRANSIT` → `DELIVERED` → `INSTALLED`
- **Date Tracking:** Manufacture, supply, warranty, and inspection dates
- **Warranty Management:** Active, Expiring Soon, and Expired alerts
- **Vendor Analytics:** Performance and risk tracking synced from GaugeMarket

### 2. TMS (Transport & Monitoring System)
Owns the complete shipment lifecycle and technician inspection records.
- **Shipment Tracking:** Real-time event timeline (`CREATED` → `PICKED_UP` → `IN_TRANSIT` → `DELIVERED`)
- **Risk Assessment:** High/Medium/Low risk profiling generated by technician inspections
- **Tracking Portal:** Publicly accessible shipment status lookup (`/view/<uid>`)
- **Order Sync:** Automatic ingestion of dispatched orders from GaugeMarket

## 🔒 Secure Admin Registration System

To protect sensitive supply chain and tracking data, the entire portal is secured using an **Admin-Only** architecture.

- **Multi-Admin Support**: Stores admin profiles (Name, Email, Phone, Railway Division, Employee ID) in the database.
- **Invite Key System**: New administrators can only register by providing the official **Secret Invite Key**.
- **Cryptographic Security**: Passwords are securely hashed via `werkzeug.security`.

## 🔄 End-to-End Data Flow

1. **Component Registered (GaugeMarket)**
   Vendor registers component; QR identity created. Payload is pushed to UDM.
2. **UDM Record Created (This Portal)**
   Digital record synced; lifecycle set to `REGISTERED`; vital dates logged.
3. **Listed & Ordered (GaugeMarket Marketplace)**
   Customer places order; payment confirmed; lifecycle updates to `PURCHASED`.
4. **Shipment Created (TMS)**
   Vendor dispatches order; TMS receives shipment notification; tracking number assigned.
5. **In Transit (TMS Tracking Events)**
   Events logged: `PICKED_UP` → `IN_TRANSIT` → `ARRIVED_AT_HUB` → `OUT_FOR_DELIVERY`.
6. **Delivered & Updated**
   TMS fires callback → UDM lifecycle updates to `DELIVERED` → Railway Division takes possession.

## 🛠️ Tech Stack

- **Backend:** Python 3.10+, Flask
- **Security:** `werkzeug.security`
- **Frontend:** HTML5, CSS3, Bootstrap 5, Chart.js
- **Design System:** Official Indian Railways Premium Aesthetic (Saffron, Navy Blue, White)
- **Database:** SQLite Serverless (simulated via local file for demo, production ready via `cache.db`)
- **Deployment:** Vercel Serverless Functions (`@vercel/python`)

## 🚀 Getting Started (Local Development)

### Prerequisites
- Python 3.10+
- `pip` package manager

### Installation
```bash
# Clone the repository
git clone https://github.com/Debanshu2005/udm_tms_dummy.git
cd udm_tms_dummy

# Install dependencies
pip install -r requirements.txt
```

### Run Locally
```bash
python app.py
```

- **Portal Home:** `http://localhost:5000`
- From here, login to access the **UDM** or **TMS** dashboards.

## 📡 API Endpoints

The portal exposes several endpoints for GaugeMarket to sync data:
- `POST /receive_data` - Ingests new component registration data
- `POST /api/tms/shipments` - Creates new shipment records from orders
- `POST /api/tms/shipments/<id>/events` - Adds tracking events
- `POST /api/tms/inspections` - Logs technician inspection reports
- `POST /api/udm/components/<uid>/lifecycle` - Updates component lifecycle state
- `GET /api/health` - Portal health check
